## 简介
本指南面向首次接触小智语音交互服务器的开发者，目标是帮助你在最短时间内完成环境准备、依赖安装、基础配置和服务启动。项目为独立运行版本，不依赖外部主进程；通过 WebSocket 提供语音交互能力，并通过 HTTP 暴露健康检查、设备管理、对话记录查询等接口。

## 环境要求
- Node.js 版本不低于 18
- 操作系统：Windows、macOS、Linux 均可
- 网络：若需要调用外部 LLM、TTS、STT 服务，请确保服务器可访问对应接口

Node.js 版本约束由项目依赖声明中定义，确保使用较新的 Node.js 以获得稳定体验。

## 基础配置
项目支持从配置文件和环境变量加载配置。默认情况下，服务端会从项目根目录的 `config.json` 读取配置；同时可通过环境变量覆盖部分关键参数。

### 配置文件位置
- 配置文件路径：项目根目录下的 `config.json`
- 运行时可能写入音频阈值等设置到同一目录的 `config.json`

### 环境变量覆盖
以下环境变量可用于覆盖配置值：

| 环境变量 | 作用 | 默认行为 |
|---|---|---|
| `XIAOZHI_PORT` 或 `PORT` | 指定服务监听端口 | 优先使用环境变量，其次回退到配置文件中的端口 |
| `XIAOZHI_HOST` 或 `HOST` | 指定服务监听地址 | 优先使用环境变量，其次回退到配置文件中的主机地址 |
| `USE_HTTPS` | 控制 WebSocket URL 协议提示 | 值为 `true` 时，当前 WebSocket 协议显示为 `wss` |
| `NODE_ENV` | 运行环境标识 | 未设置时为 `development` |
| `STT_PROVIDER` | 语音转文字提供商 | 未设置时使用 STT 配置中的默认值 |
| `STT_LANGUAGE` | 语音转文字语言 | 未设置时使用 STT 配置中的默认值 |
| `TTS_PROVIDER` | 文字转语音提供商 | 未设置时使用 TTS 配置中的默认值 |
| `TTS_VOICE` | 文字转语音音色 | 未设置时使用 TTS 配置中的默认值 |
| `FUNASR_HOST` | FunASR 服务主机 | 未设置时使用 STT 中 FunASR 配置的主机 |
| `FUNASR_PORT` | FunASR 服务端口 | 未设置时使用 STT 中 FunASR 配置的端口 |
| `FUNASR_MODE` | FunASR 运行模式 | 未设置时使用 STT 中 FunASR 配置的模式 |

配置加载器会先读取 `config.json`，再应用环境变量覆盖，从而保证部署灵活性与可移植性。

## 启动服务
安装依赖后，可使用 npm 脚本启动服务：

```bash
npm start
```

该脚本会执行 `run-server.js`，加载 `.env`（如果存在），读取 `config.json`，创建并启动小智频道服务。

你也可以直接运行入口文件：

```bash
node run-server.js
```

启动成功后，控制台会输出 HTTP 地址、OTA 地址、WebSocket 地址和健康检查地址。

## 验证服务是否正常运行
服务启动后，可通过以下接口验证：

- 健康检查：访问 `http://localhost:<端口>/health`，返回状态、频道信息、在线设备数量和运行时长
- WebSocket 连接信息：访问 `http://localhost:<端口>/api/websocket/urls`，返回 WS/WSS 地址和当前协议
- OTA 接口：设备端可通过 `http://<主机>:<端口>/xiaozhi/ota/` 进行固件相关操作

健康检查接口会返回服务基本信息，适合在自动化部署或监控中使用。

## 常用配置选项说明
以下是与服务启动和语音交互相关的常用配置项。实际值以 `config.json` 为准，并可被环境变量覆盖。

| 配置路径 | 含义 | 说明 |
|---|---|---|
| `port` | 服务监听端口 | 可通过 `XIAOZHI_PORT` 或 `PORT` 覆盖 |
| `host` | 服务监听地址 | 可通过 `XIAOZHI_HOST` 或 `HOST` 覆盖 |
| `id` | 频道标识 | 用于区分不同频道实例 |
| `name` | 频道名称 | 用于展示和日志 |
| `desc` | 频道描述 | 用于插件元数据 |
| `stt.provider` | 语音转文字提供商 | 可通过 `STT_PROVIDER` 覆盖 |
| `stt.language` | 语音转文字语言 | 可通过 `STT_LANGUAGE` 覆盖 |
| `tts.provider` | 文字转语音提供商 | 可通过 `TTS_PROVIDER` 覆盖 |
| `tts.voice` | 文字转语音音色 | 可通过 `TTS_VOICE` 覆盖 |
| `llm.provider` | 大模型提供商 | 独立模式下通过 bridge 调用外部 LLM |
| `llm.model` | 大模型名称 | 根据提供商支持的模型填写 |
| `llm.apiKey` | 大模型 API 密钥 | 根据提供商要求配置 |

此外，服务还提供音频有效性阈值的热更新接口，可在运行时调整振幅阈值和静默阈值，并持久化到 `config.json`。

## 常见问题与解决方案

### 启动时报错 Node.js 版本过低
**现象**：安装依赖或启动时报语法错误或引擎版本不兼容  
**原因**：项目要求 Node.js 版本不低于 18  
**解决**：升级 Node.js 至 18 或更高版本，然后重新安装依赖并启动

**章节来源**
- [package.json:24-26](file://package.json#L24-L26)

### 端口被占用
**现象**：启动失败，提示端口已被占用  
**原因**：默认端口或其他进程占用了相同端口  
**解决**：通过 `XIAOZHI_PORT` 或 `PORT` 环境变量指定其他可用端口，或停止占用端口的进程

**章节来源**
- [run-server.js:31-32](file://run-server.js#L31-L32)
- [config/loader.js:53-54](file://config/loader.js#L53-L54)

### 无法访问 WebSocket 地址
**现象**：客户端无法连接 `/xiaozhi/v1/`  
**原因**：防火墙、反向代理或跨域限制导致连接失败  
**解决**：确认服务已启动且端口开放；如需 HTTPS，设置 `USE_HTTPS=true`，并确保反向代理正确转发 WSS

### 健康检查返回异常
**现象**：`/health` 返回错误或非预期状态  
**原因**：服务未完全初始化或内部组件异常  
**解决**：查看控制台日志；确认依赖安装完整、配置文件有效；必要时重启服务

### 配置加载失败
**现象**：启动时报配置加载错误  
**原因**：`config.json` 缺失或格式不正确  
**解决**：在项目根目录创建有效的 `config.json`，并确保 JSON 格式正确；也可通过环境变量覆盖关键配置
